# 林业项目组合驾驶舱领域约定

项目面向集体林权改革与林下产业协作场景。县里同时推进药材、康养、特色林、
森林人家四类项目，领导会议需要看到**统一口径、统一里程碑、可追溯来源版本**
的组合视图，而不是各单位口径不一的汇总数。

## 一、事件是唯一事实来源（只追加）

投资、产能、就业、带农户数、农户增收、生态风险、里程碑进度，全部通过统一
事件入口 `POST /api/events` 接收。事件一经写入**只能追加、不能覆盖或删除**：

- `occurred_on`：业务发生日期；`recorded_at`：入库时间（两者分离以支持补录）；
- `source`：上报单位；`source_batch`：来源批次（同一单位的一批数字共享批次）；
- 指标补报是“追加新事件”，不是修改旧事件，历史值始终可追溯；
- 服务启动（含崩溃恢复）时重放全部事件重建状态，写半行的损坏尾记录会被截断。

## 二、统一里程碑

里程碑必须取自统一目录：立项批复、用地落实、主体开工、中期验收、投产达效。
进度按权重计算里程碑完成率；到期未达成触发红色预警，晚于计划达成触发黄色
预警——避免只报一个笼统“完成率”。

## 三、统计口径与生效日期

- 系统内置基准口径 `v1`（名义万元，折算系数 1），无需定义；
- 新口径以 `caliber_defined` 事件登记，带**生效日期**；
- 资金类事件用 `reported_version` 注明上报口径，投影时折算为基准口径；
- 业务发生日早于口径生效日时拒绝接收（口径不能提前使用）；
- 任何历史日期的视图按当日生效口径重放，口径修订不会改写历史结论。

## 四、跨年度目标

目标按 `(指标, 年度)` 下达（`target_set`），区分项目级与组合级。收益等流量
指标按业务发生年度归集：年内补录进入当年“年初至今”，**跨年补录只进累计、
不污染当年完成率**。

## 五、项目合并

`project_merged` 记录“被合并方 → 存续方”，被合并方的历史事件全部保留，
指标按归并族自动归集、不重复计数；合并具有生效日，历史日期视图仍显示合并前
的独立项目。合并后的滞后票据补录到旧项目仍会归到存续方。

## 六、情景比较

情景 = 基线事件 + 该情景的叠加事件。叠加只允许调整指标、风险、约束与里程碑
达成，**不允许新增/合并项目、改口径、改目标**等结构变化，基线永不被修改。
`/api/compare` 输出各项目产能、收益、带农户数、风险、评分、名次、新增/解除
预警及组合总量的同步差异，用于季度调度推演。

## 七、排序、预警与资金转向

- 评分由投资/增收达成度、产能、就业、带农户数、里程碑进度、生态风险加权；
- 预警分级：红（逾期、生态约束触发）、黄（风险高、带农户数下降、增收滞后）、
  蓝（提示类）；
- 决策建议回答“资金与资源该转向哪里”：约束触发即冻结新增经营性投入，逾期
  项目集中拨付并提级调度，带农户数下降安排联农带农补助，高分低风险项目作为
  增量资金承接方。

## 八、权限批注

批注只追加，记录作者角色与可见范围（audience）。不同角色只能看到授权范围内
的批注，任何角色都不能覆盖、删除他人批注。

## 九、已发布视图不可变

发布（`POST /api/publish`）把某日期、某情景下的完整视图连同参与计算事件的
SHA-256 指纹固化为快照文件。之后无论新增事件还是系统重启，`view_id` 指向的
内容与指纹保持原样；当前视图与历史版本可并列对照。

## 十、信息边界

涉及个人、机构或敏感地点的信息只向职责范围内的角色开放，所有对外结果都能
追溯到采用的数据版本（事件序号、来源、批次、口径版本与指纹）。
