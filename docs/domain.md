# 林业项目组合驾驶舱领域约定

项目面向集体林权改革与林下产业协作场景，服务药材、康养、特色林、森林人家等
并行项目的县级统一调度。核心矛盾是：各单位汇总口径不一、只报"完成率"无法回答
资金与资源该转向哪里。本文件说明系统的数据与版本约定。

## 1. 只追加事件链（append-only）

所有业务记录都是不可变事件，入库即获全局递增 `seq`，并记录：

- `source`：报送来源单位（财政、人社、农业农村、乡村振兴、生态环境、住建等）；
- `effective_date`：业务发生日（里程碑日期），`recorded_at`：入库时间，二者允许倒挂；
- `caliber_version`：报送时生效的统计口径版本；
- `idempotency_key`：报送幂等键，重复报送直接拒绝；
- `supersedes`：更正指向的旧事件 seq。旧事件永远留链，新视图排除旧值，
  但切到更正事件之前的 `at_seq` 仍复现旧值。

事件类型：投资/产能/就业/增收/带农户数指标、生态风险（等级 1–5 + 约束标记）、
里程碑（计划/实际日期）、项目合并、年度目标、跨年度目标、口径版本。

## 2. 版本化视图与口径

任何视图都由切片三元组决定：`as_of`（观察日）、`at_seq`（数据版本）、
`caliber_version`（目标口径），情景视图再加 `scenario_id`。

- 指标按"年度累计最新时点"取值，目标完成率只是视图中的一个字段，不是全部；
- 口径版本带生效日期与各指标重述因子：在 v_c 口径展示 v_r 口径记录的值时，
  `value * factor[c] / factor[r]`。新视图默认采用观察日生效的最新口径，
  已发布视图永久保持发布时的口径与数值；
- 晚到的补报（早发生、晚入库）进入新视图，进不了更早发布的快照。

## 3. 项目合并

合并本身是带生效日的事件。生效日之后，被合并方的指标按成员相加、
目标按成员相加、风险取最高等级、生态约束只要任一成员触发即继承，
延期历史全部保留（合并不洗白延期）。生效日之前或合并事件 seq 之后的
历史切片中，项目仍独立呈现。

## 4. 预警与决策依据

视图对每个项目并行产出三类预警，每条预警都带触发事件 seq：

- `schedule_delay`：里程碑到期未完成或已闭环延期；
- `ecological_constraint`：风险等级 ≥4 或触发生态约束；
- `farmers_drop`：带农户数最近两个时点下降；
- `target_lag`：完成率低于年内时间进度的 90%。

排序不按单一完成率，而按决策评分：生态风险（含约束加分）、延期、
目标缺口、联农带农下滑加权求和，并输出可执行的资源转向建议
（暂停注资先整改、专项调度卡点、限期补报等）。缺报项目显式标注
数据缺口与置信度，而不是被当成完成率为 0。

## 5. 情景比较（季度调度）

情景在基线 seq 上叠加三类调整：指标增减（产能下调）、风险覆盖
（风险提升/约束）、较早日期的收益补录。情景不改动基线事件链；
试算视图与基线视图比较排序位移、新增/解除预警、评分变化与建议增减。
批准（commit）后调整以"情景固化"为来源追加为真实事件，产生新的 seq 区间。
已固化情景不可再改。

## 6. 批注权限

批注挂在项目/指标/事件/驾驶舱上，记录作者与角色。只有作者本人或
`admin` 可修改、删除；越权操作返回 403 且原内容不变——不同单位、
不同权限的批注不得互相覆盖。修改保留编辑痕迹（旧内容、新内容、
编辑人、时间），删除为软删除。

## 7. 发布视图冻结与系统恢复

发布（snapshot）保存的是渲染完成的完整 payload 与切片信息，不是查询条件。
状态整体原子落盘，重启后从文件恢复：已发布视图逐字节保持发布时版本，
补报、合并、口径变更、情景固化、批注都只追加新版本，永不回写旧快照。

涉及个人、机构或敏感地点的信息只应向职责范围内的角色开放，
所有对外结果都应能够追溯到采用的数据版本（seq + caliber_version + source）。
